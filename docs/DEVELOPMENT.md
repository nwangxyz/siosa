# Siosa — 개발 문서

Path of Exile 1 (카카오 한국 클라이언트)용 액트 진행 보조 오버레이입니다.

- 클래스별로 퀘스트 보상을 미리 골라 두면, 게임에서 보상 창이 열렸을 때 고른 보상 칸을 강조합니다.
- 게임 로그를 읽어서 현재 지역, 캐릭터 레벨, 퀘스트 완료·보상 수령 상태를 표시합니다.
- 게임 입력은 전혀 읽거나 보내지 않습니다. **화면 일부와 로그 파일만 읽습니다.**

**버그 제보 · 건의하기**: [카카오톡 오픈채팅](https://open.kakao.com/o/svXdSBTi) (프로그램 메인 화면에도 QR·버튼)

**라이선스**: [MIT](../LICENSE). Path of Exile 및 관련 이름·데이터·이미지는 Grinding Gear Games 의 것이며, 이 프로젝트는 GGG·카카오게임즈와 관계없는 팬 제작 도구입니다.

### 요구사항: 다양한 해상도 지원
- 현재 방식: 모든 위치·크기를 **게임 창 높이 비율**(높이 / 1080)로 환산하고, 인벤토리는 **게임 창 오른쪽 끝**에 붙어 있다고 계산합니다. 창 모드면 게임 창의 그리기 영역을 기준으로 합니다.
- 1080p 외에 1440p·1366x768·1280x720·21:9(1680x720)·16:10(1440x900)·창 모드를 실제 캡처로 확인 (아래 **실측**). 4K·3440x1440·1920x1200 은 아직 캡처 없음.

| 해상도 | 비율 | 확인할 점 |
|---|---|---|
| 2560x1440, 3840x2160 | 16:9 | 높이 비율 환산이 그대로 맞는지 |
| 1920x1200, 2560x1600 | 16:10 | 가로 여백이 늘 때 보상 창 가운데 위치 |
| 3440x1440, 2560x1080 | 21:9 | 울트라와이드에서 인벤토리·보상 창 위치 (UI가 가운데 영역에 몰리는지) |
| 1366x768, 1600x900 | 16:9 저해상도 | 작은 칸에서 색·아이콘 판별 정확도 |
| 창 모드 (테두리 있음) | - | 게임 창 위치 기준 계산 |

- **실측 (2026-10-22, `python -I tools\tests\resolutions.py` → 23/23)**: 실제 게임 캡처(Ctrl+Shift+D, 인벤토리 열린 상태, 쉐도우)
  | 게임 화면 | 비고 | 보상 창 |
  |---|---|---|
  | 1904x1001 | 1080p 창 모드 | 힐록 젬 6 · 플라스크 3(1x2) · 휴거 장치 젬 14(6+6+2) |
  | 2544x1361 / 2560x1440 | 1440p 창 모드 / 전체 화면 | 젬 6 · 젬 14 · 죽음과 부활 갑옷 3(2x3) |
  | 1366x768, 1280x720 | 저해상도 | 젬 6 · 플라스크 3 · 젬 14 · 갑옷 3 · 태풍의 칼 무기 6(4+2) |
  | 1680x720 | 21:9 | 젬 6 · 플라스크 3 · 젬 14 · 무기 6 |
  | 1440x900 | 16:10 | 젬 6 · 플라스크 3 · 젬 14 · 무기 6 |
  - 고친 것: 1080 으로 나누어떨어지지 않는 높이(900, 1001)에서 칸 테두리 1px 선이 두 픽셀에 나뉘어 그려져(배경 21 → 35·35)
    한 픽셀 밝기 차(+14)가 기준(15)에 못 미침 → 장비·플라스크 창 3장 실패(20/23). 두 픽셀을 합친 밝기 차도 보게 함 (`Pixels.EdgeLine`)
  - 아직 없음: 4K, 3440x1440(실제 21:9 모니터), 1920x1200, 인벤토리를 닫은 상태의 다른 해상도
- 확인 방법: `Siosa.exe --dev` 로 실행, 해당 해상도에서 보상 창을 연 상태로 Ctrl+Shift+D → `debug\reward_*.png` 를 `tools\testdata\res\<게임 화면 크기>_<보상 ID>.png` 로 옮기고 `resolutions.py`에 추가.
  어긋나면 해상도별 규칙을 실측해서 반영해야 합니다 (예전의 `Ctrl+Shift+C` 미세 조정은 위치만 옮겨 비율 차이를 못 맞추고, 게임이 앞에 있어 방향키도 못 받아 없앰).
- 모의 테스트 (`python -I tools\tests\scaled.py`): 1080p 스크린샷 14장을 3840x2160·2560x1440·1600x900·1366x768·1280x720 로
  늘리고 줄여서 판별 → 70/70. 실제 화면이 아니라 늘리고 줄인 그림이라 16:9 높이 비율 환산만 확인되고, 화면 비율(16:10·21:9)과 창 모드는 실측 필요.
  - 이 테스트로 고친 것: 칸 테두리 선 찾기 폭(±2px, 양옆 3px)이 1080p 고정이라 4K 에서 거의 모두 실패(5/14)
    → 해상도 비율만큼 넓힘. 작은 해상도는 1px 선이 흐려지므로 밝기 차 기준(18)도 비율만큼 낮춤(720p: 12)

## 사용법

1. `Overlay\bin\out\Siosa.exe` 실행 → **메인 화면** (실행할 때마다 처음부터. 진행 상황(지역·레벨·☑·포인트)은 이어서 읽음)
   - `새로 만들기` / `PoB 불러오기` → 편집 화면
   - 저장한 프리셋 목록 (최근 수정 순): `열기` → 편집 화면에서 확인 후 시작. 다른 폴더의 파일은 `파일에서 불러오기…`
   - 사용법 4줄, 게임 로그 연결 상태
   - 메인 화면과 편집 화면은 한 창 안에서 바뀜 (편집 화면 왼쪽 위 `← 처음으로`)
2. 편집 화면: 클래스 선택 → 퀘스트별로 받을 보상 클릭 → `저장` / `시작` / `초기화` (클래스를 바꾸면 선택이 비워짐)
   - 기본은 젬 보상 퀘스트만 표시. `장비·플라스크 보상도 선택`을 체크하면 장비·플라스크 퀘스트도 표시
     (끄면 고른 장비 보상을 확인 후 해제, 장비를 고른 프리셋을 불러오면 자동 체크). 젬과 장비가 섞인 퀘스트는 없음 (젬 14 / 장비 19)
   - 오버레이 실행 중 설정을 열면 `시작`이 `중지`로 바뀜: 누르면 오버레이만 끄고 설정창은 유지
   - 설정창 X 는 언제나 프로그램 종료
   - 보상 탭 액트 2 맨 위: 도적 처리 (모두 처치 / 알리라 / 크레이튼 / 오크 돕기, 기본 모두 처치)
   - `PoB 불러오기`: PoB 코드 또는 링크(pobb.in, pastebin, poe.ninja)에서 클래스와 젬만 읽어 젬 보상 퀘스트를 자동 선택 (젬 보상은 덮어씀, 같은 클래스면 장비 선택 유지). 도적 선택(PoB `bandit`: None=모두 처치 / Alira / Kraityn / Oak)도 가져옴
     - 링크는 원본 코드 주소에서 받음 (`pobb.in/<id>/raw`, `pastebin.com/raw/<id>`, `poe.ninja/poe1/pob/raw/<id>`), 불러오기를 누를 때 한 번만 접속, 10초 제한
     - 젬은 내부 ID(`gemId`)로 맞춤 (보조 젬 이름 차이·변형 젬 상관없음)
     - 스킬 세트가 여러 개면 쓸 세트를 고름. 이름에 Act/Lv/레벨/액트 등이 있고 맵·엔드게임·스왑이 없는 세트를 미리 체크 (레벨링 세트가 없어 보이면 전부)
     - 한 퀘스트에 빌드 젬이 여럿이면: **빌드에서 더 일찍 쓰는 젬**(스킬 세트 순서, 한 세트면 젬 없는 이름 묶음 "1Lv"/"8Lv" 구간) > 메인 스킬 묶음 > 큰 링크 > 스킬 젬 > 보상 창 순서
       (단계를 먼저 보지 않으면 엔드게임 세트의 큰 링크 젬이 뽑힘: 1장에 화염 벽 대신 맵용 서리 폭탄)
     - 보상으로 받지 않는 빌드 젬은 구매 목록으로, 스킬 묶음(링크)은 프리셋에 저장 (`buy`, `buyOff`, `groups`)
   - 편집 화면 탭: `퀘스트 보상` / `젬 구매 (N)` (버튼형 탭, N = 상점에서 살 젬 수)
     - 구매 목록: 이 클래스가 가장 먼저 살 수 있는 곳별로 `N장 · NPC` → `○○ 완료 후: 젬…`, 상점에서 판매하지 않는 젬, 처음 시작할 때 받는 젬, 퀘스트 보상으로 받는 젬
     - 젬마다 체크 해제(오버레이에서 숨김)·× (목록에서 빼기). 퀘스트 보상으로 고른 젬은 자동으로 구매 목록에서 빠짐
     - 처음 시작할 때 받는 젬(스킬 1 + 보조 1, GGPK `Characters.StartSkillGem` / `StartSupportGem` → `classes.json` `start`)도 구매 목록에서 빠짐 (예: 머라우더 묵직한 타격·무자비 보조). 편집 화면에서는 `처음 시작할 때 받음` 카드
     - 젬 검색: 한국어·영문 일부 → 어디서 살 수 있는지 + `추가` (PoB 없이도 구매 목록을 만들 수 있음). 추가해도 결과는 그대로(여러 개 추가), 검색칸 ✕ 또는 Esc 로 닫기
   - 편집 화면 `링크` 탭: 단계(Act 1, 8Lv …)별 링크 묶음. 묶음마다 필요한 소켓 색(`B-G-B`)과 젬(소켓 색 글자)
     - PoB 에서 가져옴: 스킬 세트가 단계, 한 세트 안에 젬 없는 이름 묶음("8Lv", "31Lv 도서관")이 있으면 그 구간이 단계
     - 직접 수정: 단계 추가·이름 바꾸기·위아래·삭제, 묶음 추가·삭제, `+ 젬`(젬 고르기 창: 검색, 더블클릭/Enter)·× 로 젬 빼기
     - `◉ 표시 중` = 오버레이에 보여 줄 단계 (자동으로 단계를 정하지 않음. PoB 레벨 표기가 일정하지 않아서)
     - 예전 프리셋의 평면 묶음(`groups`)은 열 때 단계별(`links`)로 옮김. 한 세트 구간 나누기는 PoB 를 다시 불러와야 생김
     - 판매 목록: `data/vendor.json` — 퀘스트 상점 목록은 GGPK 에 없어서 PoE 위키(Cargo `vendor_rewards`, 1306줄·457종)에서 `fetch_vendor.py` 로 받음.
       새 리그 젬은 위키 반영이 늦으면 "상점에서 판매하지 않음"으로 나올 수 있음
3. `시작`하면 오버레이가 뜨고 트레이에 아이콘이 생깁니다
   - 트레이 더블클릭: 설정 다시 열기 / 메뉴: 설정 열기, 종료
   - 설정창을 열면 오버레이를 **중지** (진행 기록·로그 위치 저장). `시작`을 누르면 같은 프리셋은 저장한 위치부터 이어 읽어 그사이 플레이도 반영
     (예전: 숨기기만 하고 버튼은 `중지`라 다시 보려면 중지 → 시작. X 는 그대로 프로그램 종료)
   - 설정창이 떠 있는 동안 설정 열기를 또 누르면 새로 열지 않고 그 창을 앞으로 (예전: 누를 때마다 하나씩 더 열림). `실행 중` 알림 풍선은 처음 시작할 때만
4. 게임은 **창 모드 또는 전체 창 모드**여야 합니다 (전체화면 모드에서는 오버레이가 보이지 않음)

### 단축키 (기본값, 모두 Ctrl+Shift+)
메인 화면 사용법 카드의 `단축키 변경`에서 바꿀 수 있습니다 (`HotkeyForm`, 설정 `hotkeys` 에 바꾼 것만 저장).
- Ctrl 또는 Alt 가 들어간 조합만 허용 (게임 채팅 입력과 겹치지 않게). 같은 키 중복은 저장 불가, 다른 프로그램이 쓰는 키는 저장 전에 경고
- 설정창을 여는 동안 오버레이 단축키는 풀어 두고, 닫을 때 바뀐 키로 다시 등록. 등록 실패한 키는 오버레이에 표시
- 메인 화면·오버레이·링크 탭의 안내 문구도 바꾼 키로 표시 (`Hotkeys.Summary` / `Short`)
- 오버레이 맨 아래 안내 줄은 자주 쓰는 다섯 개만: `Ctrl+Shift+  W 이동 · E 숨기기 · L 링크 · P 트리 · T 팁` (예전 `보상 창을 열면 자동 강조 · R 수동 · C 위치 확인 · L 링크`)
- 개발용 `Siosa.exe --hotkeytest <결과.txt>`: 키 입력 흉내(정상 변경·수정키 없음·Esc·중복·Alt 조합·저장)

| 키 | 기능 |
|---|---|
| W | 오버레이 이동 모드 |
| E | 오버레이 숨기기/보이기 |
| D | (개발용, `Siosa.exe --dev` 로 실행했을 때만) 게임 화면 캡처 + 판별 정보 (`debug\`). 일반 실행에서는 등록·안내·단축키 변경 창 모두 없음 (`Hotkeys.DevMode`) |
| L | 링크 표시 켜기/끄기 |
| J | 이전 링크 단계 (처음 이전은 마지막, 링크가 꺼져 있으면 켬) |
| K | 다음 링크 단계 (마지막 다음은 처음, 링크가 꺼져 있으면 켬) |
| T | 지역 팁 표시 켜기/끄기 (상태는 `settings.json` `showTips` 에 저장) |
| P | 패시브 트리 창 켜기/끄기 (`showTree`) |
| U / I | 이전 / 다음 트리 단계 (트리 창이 꺼져 있으면 켬) |
| = / - | 트리 창 크게 / 작게 (그림 높이 160~720px, 40px씩, `treeSize`) |

### 오버레이 표시 (현재 액트의 보상 목록)
- 패시브 트리 창 (`TreeWindow`, 오버레이와 따로 뜨는 창): `트리 · 단계 이름 (i/n · U 이전 · I 다음 · -/= 크기)` + 그림. 전체 트리는 흐린 점·선, 찍은 길은 금색, 앞 단계보다 새로 찍은 길은 초록
  - 클릭은 게임으로 통과. 오버레이 이동 모드(W) 동안 같이 끌어서 옮길 수 있고 위치는 `treeX`/`treeY` 에 저장
  - 오버레이를 숨기거나(E) 설정창을 여는 동안은 같이 숨김
  - 노드·선 두께는 찍었어도 안 찍은 것과 같음 (1px, 색으로만 구분). 마스터리는 흐린 고리, 찍은 마스터리는 금색·초록 고리
  - 오른쪽 열: 위에 찍은 전직 트리(찍은 노드가 가장 많은 전직 하나), 아래에 고른 마스터리 효과 한국어 목록 (`화염 숙련: 물리 피해의 40%를 화염 피해로 전환`, 그 단계에서 새로 고른 것은 초록)
  - 단계 = PoB 트리(Spec)들 (`8Lv`, `Act.3`, `lvl 47` …). PoB 불러오기 때 전부 가져옴(`masteryEffects` 포함), 편집 화면 `패시브 트리` 탭에서 고르기(★ = 미니맵 단계)·삭제
  - 데이터: 카카오게임즈 공식 패시브 트리 페이지(`poe.kakaogames.com/passive-skill-tree`, 3.29.3b)의 트리 데이터(한국어, GGG skilltree-export 와 같은 형식)를 `Extractor/fetch_tree_ko.py` 로 받아 `build_tree.py` 로 노드 위치·연결·마스터리 문구만 남긴 `data/tree.json` (약 250KB, 본 트리 + 전직 37개). 클러스터 주얼·블라이트 노드는 그리지 않음
  - 샘플 PoB 3개(트리 3.27·3.28)의 노드 1556개·마스터리 효과 76개가 모두 3.29.3b 데이터에 있음 (없는 노드는 건너뜀)
- 지역 팁: 경험치 패널티 줄 바로 아래 `팁  내용` (34자마다 줄바꿈, 이어지는 줄은 내용 시작에 맞춤). 142개 지역 기본 팁
  - 내용: 레이아웃 팁 (다음 지역·웨이포인트 위치, 구별하는 지형지물, `[건너뛰기]` 가능 지역). 방향(왼쪽·오른쪽·위)은 화면 기준이고 시드에 따라 다를 수 있음
  - 출처: [Maxroll 캠페인 가이드](https://maxroll.gg/poe/getting-started/campaign-guide) (Enki 작성, Raxxanterax·Tytykiller 검수, 2025-06-06 갱신)를 한국어 지역·NPC 이름으로 옮김
  - 기본값 `data/tips.json` (지역 ID → 한 줄). 주석 없는 순수 JSON (읽을 때 `//` 로 시작하는 줄은 건너뛰므로 주석을 다시 넣어도 동작함, `GameData.StripLineComments`)
  - 편집 화면 `지역 팁` 탭에서 고침. 고친 것만 `settings.json` `tips` 에 저장(모든 프리셋 공통), 비우면 그 지역 팁 숨김, `기본값`/`모두 기본값` 으로 되돌림
- 은신처(`Hideout…` 지역)는 `은신처 · Lv N` 한 줄만 (보상·포인트 줄은 액트 지역에서만). 그 밖의 액트 밖 지역(지도 등)은 `액트 밖 지역`
- 패시브·재설계 포인트를 액트 밖(은신처에서 책 사용 등)에서 얻으면 마지막으로 있던 액트(`lastAct`)로 셈 (예전: 버려짐)

### 정규식 탭 (상점 검색)
- 단축키 두 개, 둘 다 클립보드에 넣고 → 상점 검색칸을 누르고 `Ctrl+V` (키 입력은 보내지 않음, `RegexSearch`)
  - `Ctrl+Shift+G` 구매 젬: 지금 액트(은신처면 마지막 액트)에서 살 젬 이름만 `"젬1|젬2"` (`RegexSearch.BuildBuy`)
    - 오버레이 `구매` 줄과 같은 기준 (`RegexSearch.BuyGems`: 체크한 젬 중 보상·시작 젬으로 받지 않고 이 액트에서 처음 살 수 있는 것)
  - `Ctrl+Shift+F` 정규식: 직접 입력 + 자주 쓰는 정규식을 `|` 로 이어 따옴표 하나로 `"직접 입력|자주 쓰는 것"`
  - 둘을 섞지 않는 이유: 옵션 정규식(이동 속도 등)과 젬 이름을 같이 넣으면 젬이 아닌 아이템까지 강조됨 (예전 `regexBuy` 옵션은 없앰, 프리셋에 남아 있어도 무시)
  - 카테고리마다 따옴표로 묶는 `"a"|"b"` 형식은 게임 검색에서 동작하지 않아 항상 따옴표 하나 (예전 설정 `regexOneQuote` 는 무시)
- 탭 순서: 구매 젬(단축키·설명) → 미리보기(F 로 복사될 내용, 글자 수) → 직접 입력 → 자주 쓰는 정규식
- 오버레이 맨 아래 단축키 줄·메인 화면 단축키 안내에도 G·F 표시
- 게임 검색은 공백을 AND 로 나눔(따옴표 안에서도) → 젬 이름·자주 쓰는 정규식의 공백은 `.` 로 바꿈 (`겨울 보주` → `겨울.보주`, `RegexSearch.NoSpace`). 직접 입력은 그대로
  - 예 (위치 PoB 샘플): G 3장 `"기세.보조|겨울.보주|체온저하.보조|영감.보조|얼음.쐐기.보조|가속"` · F `"이동.속도|이동.속도.\d+%.증|-\w-\w-"` (`--hotkeytest` 에 출력)
- 직접 입력(`regexCustom`), 고른 자주 쓰는 정규식(`regexPresets`)은 프리셋마다 저장
- 자주 쓰는 정규식 목록은 `data/regex.json` (개발할 때 고쳐 빌드에 넣음)
  - 항목: `{"id": "move", "name": "이동 속도 (신발)", "pattern": "이동 속도 \\d+% 증", "note": "툴팁 설명"}`
  - 묶음 항목: 속성처럼 한 단어만 다른 식은 `options` 로 묶고 `pattern` 의 `{}` 자리에 고른 것을 `|` 로 이어 넣음
    `{"id": "add", "name": "피해 #~# 추가", "pattern": "^({}).*추가", "options": ["물리", "화염", "번개", "냉기", "카오스"]}`
    → 물리만 `^(물리).*추가`, 물리+화염 `^(물리|화염).*추가`. 설정창에는 한 줄에 이름 + 선택지 체크 (식은 표시하지 않음, 합친 결과는 미리보기에). 카드 설명: `# 으로 표시된 옵션은 수치 상관없이 전체 강조`
    - 프리셋에는 `id:선택지` 로 저장 (`add:물리`). `options` 가 있는데 `{}` 가 없으면 그 항목은 건너뜀 (`debug\siosa.log`)
    - 지금 묶음: 피해 추가(물리·화염·번개·냉기·카오스), 주문 시전 시 피해 추가(화염·번개·냉기), 모든 주문 스킬 젬 레벨(화염·번개·냉기·물리·카오스), 지속 피해 배율(화염·냉기·물리·카오스)
  - JSON 이라 정규식의 `\` 는 `\\` 로 두 번 씀. 공백은 그대로 써도 복사할 때 `.` 로 바뀜. `//` 로 시작하는 줄은 주석
  - `id` 는 프리셋에 저장되는 이름 (바꾸면 그 항목을 골라 둔 프리셋에서 체크가 풀림). 없으면 `name` 을 씀. 이름·식이 빈 항목, 같은 id 는 무시
  - 파일을 읽지 못하면(형식 오류) 목록이 비고 탭에 빨간 안내, `debug\siosa.log` 에 이유 (`GameData.LoadRegex`)
- 기본 10개: 옵션 문구는 카카오 GGPK `metadata/statdescriptions/stat_descriptions.txt` 의 한국어 문구에서 확인
  (`이동 속도 {0}% 증가`, `물리 피해 {0}~{1} 추가`, `장착된 화염 속성 젬 레벨 {0:+d}`, `생명력 최대치 {0:+d}`, `화염 저항 {0:+d}%` …)
  - 소켓 연결(4링크 `-\w-\w-`, 3링크 `\w-\w-\w`)은 Maxroll PoE1 레벨링 가이드의 상점 검색식(`-[rgb]-.-`) 기준. 한국어 클라이언트에서 소켓을 R/G/B 로 찾는지 게임 확인 필요
- 미리보기(구매 젬 제외, 복사 버튼 없음 — 복사는 게임 중 단축키): 카테고리별 조각 + 최종 문자열 + 글자 수 (250자 넘으면 빨간색, 게임 검색칸 제한은 PoE1 영문판 기준 250자)

### 저장·안정성
- 프리셋 저장: 프리셋 ID(= 진행 기록 파일 이름)는 파일마다 다르게
  - 연 프리셋의 이름을 바꿔 저장하면 `이름 바꾸기`(ID·진행 그대로, 예전 파일은 휴지통) / `복사본`(새 ID) 중 고름 (예전: 같은 ID 파일이 둘이 되어 진행 기록을 같이 씀)
  - 같은 이름의 다른 프리셋이 있으면 덮어쓸지 묻고, 덮어쓰는 파일은 휴지통으로 (예전: 이름을 비우면 기본 이름이라 묻지 않고 덮어씀)
  - 저장하지 않은 변경·저장한 적 없는 프리셋으로 `시작`하면 저장하고 시작할지 물음
  - 개발용 `Siosa.exe --savetest <빈 폴더> <결과.txt>`: 새로 저장 → 이름 바꾸기 → 복사본 → 덮어쓰기(아니요/예)
- 단축키(J/K, U/I)로 바꾼 링크·트리 단계는 시작한 프리셋 파일에 저장 (두 값만 바꿈, `SiosaApp.SaveStages`)
- 설정·프리셋·진행 기록은 `파일.tmp` 에 다 쓴 뒤 바꿔치기 (`SafeFile`): 쓰는 도중 꺼져도 원래 파일이 남음
- 로그는 4MB 씩 나눠 읽음 (예전: 남은 만큼을 한 번에 → 오래 꺼 둔 뒤 GB 단위면 멈추거나 메모리 부족). 저장 위치는 마지막으로 다 읽은 줄의 끝 (쓰는 중인 줄을 건너뛰지 않음)
  - `--chartest` 에 9MB 한글 로그(4MB 경계에 걸린 줄)·쓰는 중인 줄 확인 포함
- 오버레이·트리 창의 저장된 위치가 어느 화면에도 보이지 않으면(모니터·해상도 변경) 기본 위치로 (`Ui.OnScreen`)
- 숨기기(E)를 누르면 보상 강조 상자도 같이 숨김
- 로그 자동 찾기: 알려진 설치 폴더·레지스트리에서 먼저 찾고, 없을 때만 실행 중인 게임 프로세스의 경로를 조회

### 캐릭터 여러 개: 프리셋 = 캐릭터
- 진행 기록(지역 방문·레벨·포인트·받음)은 프리셋마다 따로 (`progress\<프리셋 ID>.json`, 프리셋 `id`. 예전 프리셋은 파일 이름으로 `file-이름`)
  - 오버레이를 a 프리셋으로 시작하면 a 의 기록을 그 기록의 읽던 위치부터 이어 읽음 → 1번(a) → 2번(b) → 1번(a) 처럼 번갈아도 섞이지 않음
- 프리셋마다 캐릭터 이름을 기억 (처음 레벨업한 이름, `charName`). 접속할 때는 로그에 이름이 없어서 아래 규칙으로 판단
  - 이름이 정해진 프리셋에서 새 캐릭터 시작(레벨 1 황혼의 해안 접속)을 보면 → 다른 캐릭터(`foreign`): 위치만 보여 주고 방문·포인트·받음은 기록하지 않음. 오버레이에 `다른 캐릭터로 보여 기록을 멈춤 · '이름' 레벨업하면 다시 기록`
  - 기억한 이름의 레벨업·사망 줄이 나오면 다시 기록. 다른 이름의 레벨업은 파티원일 수 있어 무시만 함
  - 한계: 다른 캐릭터로 보인 뒤 원래 캐릭터로 접속하면, 레벨업·사망 줄이 나오기 전까지는 기록이 멈춰 있음
- 편집 화면 아래쪽 `캐릭터: 이름 · Lv N ▾` 버튼 (기록 없으면 `캐릭터: 아직 없음 ▾`). 누르면 메뉴: `이전 진행 불러오기 (이미 키우던 캐릭터)` / `새 캐릭터로 시작 (진행 초기화)` (기록을 비우고, 초기화 뒤 처음 레벨업하는 캐릭터가 이 프리셋 캐릭터. 누르기 전 진행은 읽지 않으므로 새 캐릭터용으로 안내)
  - 예전: 글자 + 버튼 두 개를 따로 놓아 아래쪽 줄이 넘치면 캐릭터 글자가 다음 줄로 밀려 안 보였음
- 새 프리셋을 처음 시작하면 **로그의 지금 끝부터** 읽음 (예전 로그로 캐릭터를 추측하지 않음)
  - 예전: 최근 로그 16MB 를 다시 읽고 처음 나온 레벨업 이름으로 정함 → 몇 달 전 캐릭터·파티원이 잡힘
- `이전 진행 불러오기` (캐릭터 버튼 메뉴): Siosa 없이 키우던 캐릭터를 로그에서 골라 그 진행(방문 지역·포인트)을 다시 읽음
  - 목록: 로그 전체의 레벨업 줄에서 이름·직업·마지막 레벨·시각 (최근 순 12개, 65MB 약 0.25초). 파티원도 섞이므로 사용자가 고름
  - 새로 만든 기록(로그인 → 레벨 1 황혼의 해안 → 2레벨)이 있으면 그 로그인 줄부터, 없으면(`만든 기록 없음`) 처음 보인 접속부터 읽음
  - 다시 읽는 동안은 고른 이름의 레벨업에만 묶음 (`Tracker.Adopt`). 트레이의 `로그 다시 읽기`는 없앰 (같은 추측 방식이었음)
  - 한계: 고른 캐릭터 뒤에 (새로 만들지 않은) 다른 기존 캐릭터로 접속한 구간은 구분할 수 없어 방문 기록에 섞일 수 있음
- 개발용 `Siosa.exe --chartest <결과.txt>`: 1번 캐릭터 → 2번 새로 만듦 → 파티원 레벨업 → 1번 복귀(사망 줄) 로그로 구분 확인 + 새 프리셋은 끝부터 + 캐릭터 목록·불러오기. `--charpick <png>`: 실제 로그로 선택 창 그림
- 링크 (Ctrl+Shift+L): `링크 · 단계 이름 (1/3 · J 이전 · K 다음)` + 묶음마다 `B-G-B  젬 ─ 젬 ─ 젬` (젬 이름은 소켓 색)
- 젬 구매: 마을·보상 NPC 지역에서 `구매 · NPC: 젬, 젬…` (이 액트에서 처음 살 수 있는 젬, 체크한 것만, 한 줄 4개). 샀는지는 알 수 없어 그 액트에 있는 동안 계속 표시
- 퀘스트 보상 줄(☑ ✔ ◐ ·)도 마을·보상 NPC 지역(도서관 시오사, 항구 페어그레이브즈, 솔라리스 사원 2층 디알라 부인)에서만 표시. 사냥 지역에서는 숨김 (`AtRewardPlace`)
- 패시브·재설계 포인트: `패시브 받은/받을 · 재설계 받은/받을 (N장까지)` — 지금 액트까지 **누적**
  - 받을 수: `data/points.json` (GGPK `QuestStaticRewards` `_1`=패시브, `_7`=재설계, 합계 24 / 20, 2장 `도적 처리하기` +1 = 도적 모두 처치 보상 포함). 프리셋에서 도적을 돕기로 고르면 2장부터 받을 패시브가 1개 줄어듦
  - 나아가는 길(1장 퀘스트)은 2장에서 길을 연 뒤 1장 마을 베스텔에게 받으므로 2장 목표로 셈 (`build_data.py` `POINT_ACT`). 누적 목표: 1장 2 · 2장 5 · 3장 7 …
  - 받은 수: 로그 시스템 메시지 `] : 패시브 스킬 포인트를 획득했습니다.` / `] : 패시브 스킬 포인트 N포인트를 획득했습니다.` (10장 마지막 보상 2개) / `] : 패시브 스킬 재설계 포인트 N포인트를 획득했습니다.`
  - 액트별로 나누지 않는 이유: 메시지는 포인트를 실제로 얻은 순간(책 사용)에 찍히고 퀘스트 이름이 없어서, 8장 책을 9장에서 쓰면 구분할 수 없음
  - 새 캐릭터 시작·진행 초기화·이전 진행 불러오기 때 초기화
- 마을이 아닌 지역에서 경험치 패널티가 있으면 `경험치 -N% · 지역 Lv M (캐릭터 Lv a~b면 패널티 없음)` 한 줄 (a~b = 이 지역에서 패널티가 없는 캐릭터 레벨, 예: 지역 37 → 32~42) (10% 미만 노랑, 그 이상 빨강)
  - 공식: 안전 범위 = 3 + 캐릭터 레벨/16(내림), d = max(|캐릭터-지역| - 안전 범위, 0), 배율 = ((캐릭터+5)/(캐릭터+5+d^2.5))^1.5
  - 지역 레벨 = 로그의 `Generating level N area`, 캐릭터 레벨 = 레벨업 로그

| 표시 | 뜻 |
|---|---|
| ☑ | 보상 받음 확인 |
| ✔ | 퀘스트 완료(확실), 아직 안 받음 |
| ◐ | 퀘스트 완료(추정: 목표 지역 방문), 아직 안 받음 |
| · | 퀘스트 진행 전 |


## 동작 방식

### 로그 (`logs\KakaoClient.txt`)
- 지역 진입: `Generating level N area "ID"` (N은 **지역** 레벨)
- 캐릭터 레벨: `이름(클래스) 님이 N레벨이 되었습니다` (새 캐릭터 시작 후 처음 레벨업한 이름을 내 캐릭터로 봄)
- 새 캐릭터: 로그인 서버 접속 직후 레벨 1 황혼의 해안 (마을에서 해안으로 걸어 나가는 것과 구분)
- 퀘스트 완료(오버레이 표시용): 퀘스트를 깨야 갈 수 있는 다음 지역(✔) 또는 목표 지역 방문(◐)

### 보상 창 감지 (마을 + 마을 밖 보상 NPC 지역에서만, 0.2초마다)
- 마을 밖 보상 NPC: 시오사(도서관 `1_3_17_1`), 페어그레이브즈 선장(항구 `1_3_9`), 디알라 부인(솔라리스 사원 2층 `1_3_8_2`)
- 보상 창의 "보상을 선택하십시오" 띠와 "보상" 명판의 작은 영역 4곳 색 확인 (1회 CPU 약 0.55ms)
- 창은 내용 높이에 따라 위아래로 움직이므로 가능한 높이를 모두 대 보고 **가장 잘 맞는 높이**를 고름
- 띠가 안 보일 때 창이 아직 있는지: 칸 좌우 끝의 **테두리 선**(1px, 주변보다 18 이상 밝음)이 보이는 칸이 30% 이상(최소 1칸)이면 열린 것
  - 툴팁이 띠·명판·일부 칸을 가려도 나머지 칸의 선은 보임. 닫으면 모든 스크린샷에서 0칸
  - 실패했던 방법: 아이콘 거리(어두운 배경 ≈ 어두운 장비 그림), 판별 때 테두리 띠 픽셀과 비교(띠 대부분이 창의 어두운 바탕이라 어두운 마을 바닥과 0.6~0.7 일치 → 3장 황금 책자 창에서 Esc 후 강조가 남음)
- 띠가 보일 때 판별해 둔 아이콘이 달라지면, 같은 퀘스트의 다른 보상 창인지 확인 (보상 2개 퀘스트)
- 같은 자리에서 다른 창으로 바뀌는 것은 **같은 퀘스트의 다른 보상 창이 확인될 때만** 인정. 그 외에는 가려진 것으로 보고 강조 유지
  - (예전: 툴팁 때문에 띠 높이가 달라 보이면 새 창으로 봐서 엉뚱한 보상이 번갈아 떴음 — 얼음 골렘, 독성 혼합물)

### 어느 퀘스트의 창인지 (창이 열린 순간 1회)
0. 후보 = **지금 있는 지역의 액트** 보상만 (보상 NPC는 자기 액트 마을·지역에 있음. 퀘스트 완료 판정과는 무관)
   - 예전: 이전 액트 보상까지 후보 → 고르지 않은 9장 태풍의 칼 창에 5장 우툴라 보상이 강조됨
   - 이름이 같은 장비 보상(쌍보석 반지 3종: 5장 오리아스로 귀환, 8장 도이드리 보상)은 기본 옵션으로 이름을 나눔:
     `쌍보석 반지 (화염·번개 / 냉기·번개 / 화염·냉기)`. `build_data.py` 가 `Mods` 테이블(영문)의 Implicit 으로 붙이고, 아이콘도 베이스마다 따로
   - 고르지 않은 퀘스트도 후보에 넣고, 판별 결과가 고르지 않은 퀘스트면 테두리 없이 칸 아래에 회색 `고르지 않은 보상 · [힐록 보상]`만 표시
     (예전: 고른 퀘스트만 후보 → 고르지 않은 힐록 보상 창을 칸 수가 같은 약품 상자 보상 2로 판별)
1. 창 높이로 후보를 거름
2. 칸별 색(빨강/초록/파랑 젬)과 장비 칸 아이콘(거리 40 이하)으로 1차 판별
   - 그리고 칸 자리에 **실제 칸 테두리**(칸 좌우 끝 1px 밝은 선, 주변보다 30~44 밝음)가 75% 이상 칸에서 보여야 통과.
     배치가 반 칸 어긋난 가설은 선이 0~12로 떨어짐 (8장 도이드리 반지 4개 창에 바스티리 주얼 3개가 겹쳐 뜨던 원인), 넉넉한 기준(0.75)으로 통과. 모든 줄의 양옆 칸이 비어 있어야 함
3. 통과한 (퀘스트, 줄 배치) 조합이 둘 이상이면 **보상 아이콘 비교**로 최종 결정
   - 젬: 보상 창 아이콘은 결정 위에 스킬마다 다른 금색 문양 → 같은 색끼리도 구분
   - 장비·플라스크: 아이템 그림의 불투명한 부분만 비교
   - 1등과 2등 차이가 4 미만이면 후보를 모두 강조하고 `[대화 버튼] 이면 → 보상`으로 표시

### 받음(☑) 판정
1. 창이 닫힌 뒤 3초 안에 "퀘스트 완료" 배너 (화면 가운데 또는 인벤토리를 뺀 왼쪽 영역 가운데)
2. 창이 **닫히지 않고 같은 자리에서** 같은 퀘스트의 다른 보상 창으로 바뀜 (0.6초 이내, 보상 2개 퀘스트를 바로 진행)
3. 같은 퀘스트의 다른 보상이 이미 받음 → 이 창은 열렸다 닫히면 받음
4. 받음 처리된 창이 다시 열리면 → 안 받음으로 되돌림

## 해결이 힘든 문제점

### 1. 고른 것과 다른 보상을 받아도 알 수 없음
- 게임 실행 중에는 다른 프로그램이 마우스 입력을 **읽을 수 없습니다** (버튼 상태 조회, 저수준 마우스 훅 모두 호출 0회).
  카카오 보안 모듈(`Kgar.dll`, `Pcle.dll`)이 원인으로 **추정**합니다. 게임을 끈 상태에서는 테스트하지 않았습니다.
- 입력 후킹·주입으로 우회하는 것은 보안 모듈에 걸릴 위험이 있어 **의도적으로 하지 않습니다.**
- 현재 동작: 다른 보상을 받아도 ☑ 옆에는 프리셋에서 고른 보상 이름이 그대로 표시됩니다.

### 2. 보상이 2개인 퀘스트의 두 번째 보상
- 해당 퀘스트: 자비로운 임무, 로아 알 깨트리기, 감금된 덩치 (모두 액트 1)
- 첫 보상
  - 바로 진행: 게임이 다음 보상 창을 0.2초 만에 같은 자리에 띄움 → 받음 판정 2번
  - Esc로 닫았다가 다시 받음: 다음 창이 안 뜨고 "퀘스트 완료" 배너가 뜸 → 받음 판정 1번
- 두 번째 보상: 퀘스트가 이미 끝나서 배너가 뜨지 않음 → **수령 여부와 상관없이 열렸다 닫히면 받음** (판정 3번).
  안 받고 닫았다가 다시 열면 안 받음으로 되돌아감.
- 부작용: 두 번째 보상을 안 받고 닫은 뒤 다시 열지 않으면 ☑로 남음.

### 3. 보상 구성이 완전히 같은 퀘스트는 구분 불가
- 정화를 위한 죽음(5장) / 바스티리의 날개(8장) (주얼 3개). 후보를 현재 액트로 한정하면서 실제로는 겹치지 않음.

### 4. 실측하지 못한 부분
- 여러 줄 창: 7개(4+3), 8개(4+4)만 실측. 다른 개수는 줄 수 1~4 x 나누는 방식(앞줄 많이/뒷줄 많이/N개씩)을 모두 대 봄
- 큰 장비(2x2, 1x3, 2x3, 2x4) 아이콘의 칸 안 배치 → 액트 5 이후 장비 창 위치가 약간 어긋나고, 비슷한 장비 창끼리 구분불가가 남음
  - 실측 필요: 6장 투구, 7장 신발, 10장 갑옷, 5장/9장 무기, 8장 장갑, 3장 반지·목걸이, 2장 플라스크 8개
- 인벤토리가 열린 상태의 "퀘스트 완료" 배너 위치 (두 위치 모두 확인)

| 맞은 줄 배치를 기억 | 보상 개수마다 줄 나누기가 달라 오히려 틀림 (5개 한 줄, 7개 4+3) |
| 수동 보정(첫 칸 모서리 클릭) | 해상도 기준 자동 계산으로 대체. 미세 조정(`Ctrl+Shift+C`)과 수동 강조(`Ctrl+Shift+R`)도 없앰: 자동 강조와 같은 위치 계산이라 자동이 못 잡는 해상도에서는 같이 어긋남. 예전에 저장된 `rewardOffsetX/Y` 는 읽지 않음 |

## 배포 · 자동 업데이트
- 배포는 **exe 하나** (+ 안내 README.txt). 게임 데이터(`data\*.json`, `reward_icons.png`)·아이콘·QR 은 빌드할 때 exe 안에 넣음 (`Siosa.csproj` 의 `EmbeddedResource`, 이름 `Siosa.data.<파일>`)
  - 파일 위치 (`AppPaths`, `Program.Main`): exe 위쪽에서 `data\rewards.json` 이 있는 폴더(저장소)를 찾고, **exe 가 그 저장소의 `Overlay\` 아래**(개발 빌드 위치 `Overlay\bin\out` 등)면 **개발 실행** — Root = 저장소, Data = `data\` (지금까지와 같음)
  - 그 밖은 **포터블** — exe 옆 `SiosaData\` 를 만들어 Root 로 씀 (settings.json · profiles · progress · debug), 게임 데이터는 exe 안의 것만. 만들 수 없으면 안내 후 종료
    - 저장소 안 `dist\Siosa\Siosa.exe` 도 포터블로 돈다 → 사용자와 같은 빈 상태로 배포판 확인 가능 (예전: 위쪽에 data 가 있으면 개발 실행이라 개발용 설정·프리셋을 읽었음)
  - 데이터 읽기 (`GameData.ReadData/OpenData/DataExists`): 개발 실행은 `data\` 의 파일, 포터블은 exe 안의 것
  - 자주 쓰는 정규식 목록(`data/regex.json`)은 개발할 때 고쳐 빌드에 넣는다. 사용자는 정규식 탭의 `직접 입력`으로 추가 (메모장으로 고치는 기능은 없앰)
  - 확인 (`Siosa.exe --datatest <결과.txt>`): 개발 실행·exe 하나 실행 모두 보상 33 · 지역 211 · 젬 847 · 팁 143 · 판매 1306 · 포인트 27 · 트리 · 정규식 10 · 아이콘 · 직업 7

- 배포 파일: `release.bat` (= `release.ps1`, UTF-8 BOM 으로 저장) → `dist\Siosa-v<버전>.zip` = `Siosa\Siosa.exe` + `Siosa\README.txt`(= `docs/README.txt`). `dist/` 는 git 제외

  2. `git tag v<버전>` → `git push origin v<버전>`
  3. Actions 가 Windows 서버에서 `release.ps1 -Tag v<버전>` (태그와 AppInfo.cs 버전이 다르면 실패) → `gh release create` 로 릴리스(제목 `Siosa v<버전>`, 변경 내역 자동) + `Siosa-v<버전>.zip` 첨부. 저장소 권한(`GITHUB_TOKEN`)만 씀
  - `release.ps1` 은 저장소의 `tools\dotnet` 이 있으면 그것(이 PC), 없으면 서버에 설치된 `dotnet` 으로 빌드
  - 손으로 올릴 때: 태그 `v<버전>`, 첨부 `Siosa-v<버전>.zip` (이름이 `Siosa-` 로 시작하고 `.zip` 으로 끝나야 업데이트가 찾음)
